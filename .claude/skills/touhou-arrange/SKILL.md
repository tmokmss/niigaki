# 東方アレンジ（niigaki）

## 1. worktree を用意する

- niigaki のリポジトリで `git fetch origin` し、`git worktree add .claude/worktrees/<slug> -b <slug> origin/main` → その中で `npm ci`
- dev サーバーは公開用（4377）と分け、空きポートで `npm run dev -- --port <port>` を起動する

## 2. 楽譜を探す

- 「<曲名> 楽譜」「<英語名> MIDI」で探す。MIDI の配布はログイン必須が多い
- 無料の楽譜は次の順に探す。どこも収録曲が限られるので、無ければ次へ進む。それぞれのサイトで利用条件を確かめ、出典を曲データのコメントに書く
  - ALFetite（`https://alfetite.com/sheet-music/touhou`）：原曲に忠実なピアノ譜の PDF
  - Touhou Piano Library（`https://bloak.github.io/touhou_piano_library/`）：作品ごとのピアノ譜の PDF。画像だけの低解像度の PDF がある
  - 東方ピアノEasyモード（`https://easypianoscore.jp/`）：簡単ピアノ譜の PDF と MIDI。作品ごとの一覧から曲を選ぶ。音が省略されているので、主旋律と和音を読み、MIDI と突き合わせる。参考にしたことを明記すれば改変・公開してよい（`https://easypianoscore.jp/kenri.html`）
  - EveryonePiano（`https://www.everyonepiano.com/`）：PDF は無く、ページの譜面画像を保存して読む
- MuseScore・BOOTH の譜面は、ログイン必須か有料のことが多い
- PDF は空のディレクトリに保存する

## 3. 書き起こす

- `pdftoppm -r 300 -png <pdf> <dir>/p` でページを画像にする
- `bash .claude/skills/touhou-arrange/scripts/crop.sh <dir> <page> <y0> <y1> <x0> <x1> <name>`（座標は 100dpi 換算）で 1 段を左右半分ずつ切り出して読む。16 分音符の段は右手だけを上に余白を取り、2 小節ずつ切る
- 読む前に、その画像の五線の y 座標を決めてから音の高さを数える（ト音記号は下から E4 G4 B4 D5 F5、ヘ音記号は G2 B2 D3 F3 A3）
- 調号・臨時記号（小節の中で持続）・`8va` の範囲・タイを見落とさない
- 右手は一番上の音をメロディに、左手は低音と和音の音から小節ごとの和音を決める
- 同じ音型の繰り返しは 1 回だけ読み、ページ全体の見取り図で繰り返し箇所を確かめる

## 4. 曲データにする

- `src/pieces/<slug>.ts` に書き、`src/pieces/index.ts` に登録する。書き方は `src/pieces/green-eyed.ts` に合わせる
- メロディは `"E4 G4:2 -:4 ~:8"`（`音名:16 分音符の数`、`-` は休符、`~` は前の音を伸ばす）
- 和音は根音が A3〜G4 に入る 3 音で書く（ベースは根音の 2 オクターブ下と 1 オクターブ下を鳴らす）

## 5. Chipzel 風に組み直す

イントロで原曲を名乗り、ドロップで崩す。原曲の音をそのまま 8bit で鳴らすだけの区間を作らない。

- 4 拍子・BPM 150〜170・`groove: "four"`
- 3 拍子の原曲は、1 小節の 3 拍を「3＋3＋2」に引き延ばす（`tresillo`）。16 分音符が 12 個続く小節は、和音を駆け上がる 4 音を足して 16 個にする（`flourish`）
- 構成：イントロ 8 → ビルド 4 → ドロップ 16 → ブレイク 8 → 再ビルド 8 → ドロップ 2 16 → ドロップ 3 16
- イントロは、原曲で一番知られたフレーズ（主題やサビの頭）を原曲の和音のまま、メロディと `arp` だけで鳴らす。聞いてすぐ曲が分かるようにする。後半 4 小節でキックとハットを足す
- ビルドは、そのフレーズの頭の音型を短く切って反復し、間隔を詰めていく
- ドロップは原曲の旋律と和音進行を素材にして、次の崩し方を組み合わせる。原曲の音をそのまま並べた小節は各ドロップの半分以下にする
  - 刻み直し：長い音を同じ音の 8 分・16 分の連打やシンコペーションにする
  - オクターブ跳躍：旋律の音を 1 オクターブ上下に交互に飛ばす
  - アルペジオ分解：長い音を、和音の音を速く上下する音型に分ける
  - 反復：フレーズの頭 1〜2 拍を切り出して繰り返し、最後だけ原曲どおりに着地させる
- ドロップごとに崩し方の中心を変える（例：ドロップ 1 は刻み直し、ドロップ 2 はアルペジオ分解、ドロップ 3 はオクターブ跳躍とハモり）。各ドロップの頭 2 小節は原曲の旋律の形を残し、何のフレーズを崩しているか分かるようにする
- ブレイクは原曲の別の旋律を、和音とメロディだけで原曲に近い形で置く
- 崩して足した音は、その小節の和音の音か原曲の旋律の音にし、フレーズの最後は和音の音に着地させる
- 最後の小節は属和音（V）で終え、頭の小節で主和音に解決させてループのつなぎ目を作る
- ビルドの最後とドロップ 2 の前にスネアロール（`roll`）、各ドロップの頭にクラッシュ（`crash`）、後半のドロップにハモり（`harm`）を入れる
- 背景は `visual: "danmaku"`

## 6. 確かめる

- `npx -p typescript tsc --noEmit -p .` と `npm run build` を `> log 2>&1; echo EXIT:$?` で受ける
- worktree の中で `npx tsx .claude/skills/touhou-arrange/scripts/check.mts <slug>` を実行し、`badBars` が空（意図した休みの小節は除く）・`monoCollisions` が 0 であること、最後の小節から最初の小節への和音とメロディのつながりを見る
- `playwright-cli` でページを開いて PLAY を押し、イントロ・ドロップ 2・つなぎ目の後でスクリーンショットを撮る。コンソールのエラーが favicon の 404 だけであること
- ブラウザのログ（`.playwright-cli/`）を消してからコミットし、push して main への PR を作る

## 7. 報告する

ローカルの URL（`http://localhost:<port>/niigaki/<slug>/`）、PR の URL、楽譜の出典、目で読んだので読み違いがあり得ることを伝える。
